# v0.9.0 重大升级：供应商化 AI 模型配置 + 两阶段调用 + 本地备份 Spec

## Why
当前 AI 模型配置是「扁平组合」（`AiCombo` 单模型列表），无法体现「供应商 → 多模型」的层级，
也不支持「拆图分割 / 读题解答」两阶段分别调度模型、无法按成本优先使用非多模态模型。
设置页所有选项平铺在长滚动页，占用大量屏幕空间。解题记录与知识点掌握度只有后端云同步、
没有本地离线备份能力。

本次为 **0.9.0 中版本巨大更新**（0.7.9 → b 位 +1），产出 Android APK 与 Windows EXE 双端。

## What Changes
- **BREAKING**：将扁平的 `AiCombo` 模型配置替换为「供应商 → 多模型」层级模型
  `AiProvider` / `AiModel`。旧的 `AiCombo`、`buildModelChain()`、`availableCombos` 等
  全部废弃并移除；持久化 JSON 结构整体升级（旧数据做一次迁移兜底）。
- **两阶段 AI 调用管线**：拆图分割（多模态提取）→ 读题解答（按需标记、成本优先、异供应商并行）。
- **模型调用顺序 UI**：按「拆图分割 / 读题解答」两板块分别排序与启用，拖动重排、点击启停。
- **设置页改版**：每类选项收纳为「可点击展开」的卡片，折叠时仅显一行，减少屏幕占用。
- **本地备份**：解题记录 + 知识点掌握度可导出 JSON 文件、可导入恢复。
- 版本号提升至 `0.9.0+27`，同步更新设置页底部角标文案与双端发布。

## Impact
- Affected specs：AI 模型配置（combo → provider）、AI 调用（阶段化）、设置页、数据备份。
- Affected code（主要）：
  - `lib/models/ai_combo.dart` → 新增 `lib/models/ai_provider.dart`（供应商+模型），`ai_combo.dart` 废弃。
  - `lib/providers/settings_provider.dart`（模型配置增删改、两阶段排序、迁移旧数据）。
  - `lib/services/ai_service.dart`（拆图 / 解答提示词、并行调用入口；`generateRaw` 复用于拆图）。
  - `lib/services/failover_manager.dart`（阶段化 Failover，支持并行）。
  - `lib/providers/solve_provider.dart`（两阶段管线：拆图→答案库→带标记/普通分类解题）。
  - `lib/screens/combo_edit_screen.dart` → 新增供应商编辑页 + 模型编辑页 + 调用顺序页。
  - `lib/screens/settings_screen.dart`（可展开卡片式改版 + 备份入口）。
  - `lib/data/daos/solve_record_dao.dart`、`lib/data/daos/knowledge_dao.dart`（备份导出/导入取数）。
  - `pubspec.yaml`、`lib/screens/settings_screen.dart`（版本号 → 0.9.0）。

## 术语约定
- **供应商 Provider**：一份 Base URL + 一个 API Key + 多个模型；可自定义名称。
- **模型 Model**：隶属于某供应商，可在 API 层显示为某个 model id；可自定义名称；标识是否多模态。
- **用户模型名**：界面统一展示为 `编号 + 供应商名称 + 模型名称`，形如 `1-1 Deepseek V4.1Flash`，
  其中 `1-1` 为模型唯一编号（供应商序号-模型序号，从 1 起）。
- **拆图分割阶段（Stage A）**：用多模态模型把图片里的题目文字提取、图片理解转述，并将数学绘图
  转成文本/结构化数据。无法转换的题标记为「需多模态」，进入读题解答阶段优先用多模态解题。
- **读题解答阶段（Stage B）**：对已标记的题优先多模态解题；未标记的题优先非多模态（省经费）；
  命中答案库直接出答案；若多模态组与非多模态组来自不同供应商（以 Base URL + API Key 判定）
  则可并行发送解题。

## ADDED Requirements

### Requirement: 供应商化 AI 模型配置模型
系统 SHALL 提供「供应商 → 模型」的分层配置模型，替代旧的扁平组合列表。

- 每个供应商包含：自定义名称、Base URL、API Key、若干模型。
- 每个模型包含：唯一编号、自定义名称、API model id、是否多模态；以及其在
  「拆图分割 / 读题解答」两阶段各自的启用状态与顺序。
- 模型唯一编号 SHALL 以「供应商序号-模型序号」派生（如供应商 1 的模型 1 为 `1-1`），序号按
  供应商列表中顺序、供应商内模型列表顺序从 1 开始。

#### Scenario: 用户添加供应商与多个模型
- **WHEN** 用户在设置页添加一个供应商（含 Base URL / API Key / 名称）并添加多个模型
- **THEN** 每个模型自动获得唯一编号（如 `1-1`、`1-2`），并以「编号 + 供应商名 + 模型名」
  作为用户模型名在界面展示。

#### Scenario: 旧版扁平组合数据迁移
- **WHEN** 用户从 ≤0.7.9 版本升级，本地存有旧的 `AiCombo` JSON
- **THEN** 应用将按「每个旧组合近似为一个供应商（含单模型）」做一次迁移，不丢弃原配置；
  迁移失败/无数据时使用内置默认供应商模板。

### Requirement: 两阶段调用管线
系统 SHALL 按「拆图分割 → 读题解答」两阶段调度模型解题。

- **Stage A（拆图分割）**：按拆图分割阶段的启用顺序调用多模态模型，把图片题目提取为文本/
  结构化 JSON；无法转换的题标记为「需多模态」。该阶段全失败或无多模态模型时可回退整图路径。
- **Stage B（读题解答）**：
  - 先做答案库匹配（散题 hash + 卷次题号），命中直接出答案（不调 AI）；
  - 已标记（需多模态）的题优先调用「读题解答」阶段的多模态模型；
  - 未标记的题优先调用「读题解答」阶段的非多模态模型（省经费），失败再回退多模态；
  - 若多模态组与非多模态组模型来自不同供应商（Base URL + API Key 均不同）且都需解题，
    则 SHALL 并行发送两组请求后再合并结果。

#### Scenario: 图片中有普通文字题
- **WHEN** 拆图分割成功把题目转成纯文本、未标记需多模态
- **THEN** 读题解答阶段优先用非多模态模型解题（省经费）。

#### Scenario: 图片中含有难以转换的数学绘图
- **WHEN** 拆图分割把该题标记为「需多模态」
- **THEN** 读题解答阶段优先用多模态模型解题。

#### Scenario: 多模态与非多模态来自不同供应商
- **WHEN** 需多模态的题与普通题分别会由不同 Base URL/API Key 的供应商模型解题
- **THEN** 两组请求并行发送，任一失败按其阶段内顺序 Failover，最后合并结果返回。

### Requirement: 模型调用顺序 UI
系统 SHALL 在 AI 模型组合界面提供「拆图分割」与「读题解答」两个板块，分别配置模型顺序与启用。

- 拆图分割板块 SHALL 仅列出多模态模型。
- 用户 SHALL 通过拖动调整板块内模型顺序（即调用顺序），并点击模型切换其在该阶段的启用状态。
- 所有展示项统一为「用户模型名」（编号 + 供应商名 + 模型名）。

#### Scenario: 调整拆图分割模型顺序
- **WHEN** 用户在拆图分割板块拖动某个多模态模型到首位
- **THEN** 拆图分割阶段将优先调用该模型。

### Requirement: 设置页卡片化改版
系统 SHALL 将设置页重构为「点击卡片展开配置」的交互，减少默认占用的屏幕空间。

- 每类设置（AI 模型组合、解题设置、外观、账户、后端与数据、存储与缓存、关于/更新、故障码）各为一
  个可折叠卡片；折叠时仅显示一行标题（含关键摘要），点击展开全部配置。
- AI 模型组合卡片为其中最复杂的入口，点击后进入独立的组合配置页。

#### Scenario: 折叠展开容器
- **WHEN** 用户点击设置页某类卡片标题
- **THEN** 该卡片展开显示配置内容，其余卡片保持折叠。

### Requirement: 本地备份与恢复
系统 SHALL 提供解题记录与知识点掌握度的本地导出/导入功能。

- 导出：把全部解题记录与知识点掌握度序列化为一个 JSON 文件，按文件选择器存到本机下载目录；
  文件可离线保存、跨设备迁移。
- 导入：从文件选择器读取导出的 JSON，校验格式后批量写回本地数据库（幂等 upsert）。
- 导出/导入均在设置页「存储与缓存」类目提供入口，操作结果以 SnackBar 明确反馈。

#### Scenario: 导出备份
- **WHEN** 用户点击「导出备份」并选择保存位置
- **THEN** 生成包含解题记录与知识点的 JSON 文件，并提示保存路径。

#### Scenario: 导入恢复
- **WHEN** 用户选择本地备份 JSON 文件并确认导入
- **THEN** 备份内容被恢复/合并进本地数据库，重复导入不产生重复记录。

## MODIFIED Requirements

### Requirement: 模型调用顺序与 Failover
将原有「扁平组合顺序 Failover」重构为「两阶段 + 阶段内顺序 + 并行」的调度，
Failover 语义保留（阶段内模型失败按序切换），并新增跨供应商并行能力。

## REMOVED Requirements

### Requirement: 扁平 AiCombo 组合模型
**Reason**: 无法表达供应商多模型层级，也无法支撑两阶段调度与并行。
**Migration**: 新增 `AiProvider` / `AiModel`；旧 `AiCombo` 数据在加载时自动迁移为单模型供应商。
